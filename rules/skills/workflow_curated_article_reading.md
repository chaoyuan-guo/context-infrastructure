# 收藏文章精读工作流

## 元数据

- **类型**: Workflow
- **适用场景**: 深度阅读和理解用户明确指定的本地 Markdown 文章
- **输出**: 直接回复当前会话，不创建或修改文件
- **核心方法**: `x → f → f(x)`

## 目标与边界

把一篇文章还原成一条完整的逻辑链：作者在处理什么具体问题（`x`），给出了什么能够运转的核心回答（`f`），接受这个回答后，读者应当怎样重新理解、判断或行动（`f(x)`）。

这个 workflow 只服务于理解单篇本地文章。它不负责发现或抓取文章、追踪文中外链、扩展多来源调研、事实核查、批判性审稿或改写成其他文本。

只读取用户明确指定的本地 Markdown 文件。用户没有给出可唯一定位的文件路径时，先请用户指定；不根据标题、目录或文章内容自动扩大阅读范围。

## 阅读约束

完整读取文章后再下判断。来源、作者、发布日期等文件头用于理解语境，不代替正文证据；文章里的外链默认只是作者引用的材料，不自动继续抓取。

Superlinear 文章可能包含 `## 评论区`。评论只作为补充材料，用来提供反例、实践经验、质疑或澄清。不能把评论者的观点并入作者的 `f`；使用评论时明确标注观点归属。

始终区分三类内容：

1. 作者在正文中明确表达的主张。
2. 根据正文结构可以合理推出的解释。
3. 面向用户当前处境进一步推导的含义。

正文没有提供足够依据时，直接说明哪一环仍不确定，不用外部常识替作者补齐论证。

## 建立 x → f → f(x)

### x：作者在处理什么问题

把文章主题收成一个可以回答的问题。优先寻找作者认为既有理解在哪儿失灵、哪个现实矛盾促使他写这篇文章，以及全文反复返回的疑问。

`AI 与组织` 是主题；`AI 把执行成本降下来以后，组织为什么仍然无法获得相应的产出增益` 才是问题。

### f：作者怎样回答

提炼作者对 `x` 的核心回答，并说明它怎样运转。`f` 可以由 2 到 4 个必要部件组成，但这些部件必须共同完成一个回答。

只写 `瓶颈迁移`、`反馈闭环` 或 `Agentic Engineering` 仍然只是标签。需要写清楚因果关系、关键区分、判断顺序或方法如何处理 `x`。

从正文选择 2 到 4 个锚点支撑这条逻辑链，例如作者的案例、关键区分、数据、因果解释或反复出现的命题。锚点用于解释论证怎样成立，不按小标题依次复述全文。

### f(x)：回答怎样改变判断

把 `f` 放回 `x`，说明它改变了什么：读者会注意哪个新信号、改用什么判断标准、先问哪个问题、调整哪个行动顺序，或在哪一步停止自动反应。

根据用户当前问题决定落点。用户只想知道文章讲了什么时，以理解和判断变化为主；用户带着具体工作问题来读时，再推导相应行动。删掉 `f` 后仍然成立的普遍建议不属于 `f(x)`。

## 理解阻力扫描

完成 `f` 后，找出文章中最难仅靠文字形成清晰理解、但一旦看懂便能带动其余内容归位的机制。选择理解成本最低的表达：

| 思想形状 | 优先表达 |
|---|---|
| 前后步骤、因果传导、状态变化 | 流程图或时间轴 |
| 循环、反馈、自我强化 | 回路图 |
| 层级、部分与整体 | 结构图 |
| 两种机制反复对照 | 小表格 |
| 一两句话已经足够 | 纯文字 |

图不是固定产物。只有图能显著降低理解成本时才使用，一张通常足够。图必须呈现机制，不能只是把 `x / f / f(x)` 三行重新排列。

## 会话输出

开头先给出三行：

```markdown
- *x*：{作者在处理的具体问题}
- *f*：{作者用什么核心回答处理 x，以及它怎样运转}
- *f(x)*：{接受 f 后，理解、判断或行动发生什么变化}
```

三行之后围绕同一条逻辑链展开：解释 `x` 为什么成立，借助 2 到 4 个正文锚点说明 `f` 怎样运转，再计算 `f(x)`。文章复杂度决定篇幅，不为了覆盖所有段落而扩成摘要。

直接在当前会话交付结果。不要创建精读笔记、修改原文或写入 `contexts/curated_reads/` 的任何目录。

## 完成检查

- 已完整读取目标文章，并确认文件属于指定的两个目录之一。
- `x` 是具体问题，`f` 是能够运转的回答，`f(x)` 是由该回答推导出的变化，三者能够连读。
- 至少使用 2 个正文锚点；文章过短而不足 2 个时明确说明。
- 作者主张、合理解释和面向用户的延伸没有混在一起。
- 评论区观点没有被误写成作者观点。
- 已扫描理解阻力，并选择文字、表格或图中成本最低的表达。
- 输出只出现在当前会话，没有生成或修改文件。

## 常见失败模式

| 失败表现 | 修正方式 |
|---|---|
| 按小标题依次复述 | 回到唯一主 `x`，只保留能解释主 `f` 的内容 |
| `f` 只是术语或概念列表 | 补出部件之间的因果、区分或操作关系 |
| 从 `x` 直接跳到建议 | 先说明 `f`，再检查建议能否由它推出 |
| 用批判替代理解 | 先忠实重建作者的回答；用户要求评估时再进入审稿或事实核查 |
| 把评论当作正文 | 标明评论者身份，只把评论用于补充或挑战正文 |
| 自动补充外部材料 | 标记正文证据边界；需要外部验证时切换到调研 workflow |
